# M5 验证记录

日期：2026-10-16。范围对应 `Protocol/GAME_SPEC_V1.0.md` 第 18 节：历史纪录、更多手机布局、边界自动化、README 与实际运行错误修复。沿用 M0–M4 玩法、美术与数值。

## 已修复

- **低帧率倒计时和 Kick 停顿被拉长**：Phaser 默认平滑时钟会将开头 120 帧限制在约 16.7ms；30fps 时，3 秒倒计时可能持续约 6 秒。关闭该平滑功能；倒计时 / hit-stop 使用实际帧间隔，物理仍限制每步最多 50ms，避免卡顿后突然跳跃。暂停、后台及竖屏照常冻结全部时钟。
- **短动作测试采样过晚**：Kick、震惊和 Roll 在输入前启动浏览器内逐帧观察，Roll 的逻辑、毛球和零气泡在同一帧断言。双指测试在暂停时量取控件位置，避免云端准备期间动物已冲走；随后恢复并发送真实触摸事件。移动到边界与四帧走路按实际状态观察，测试不再假定自动化往返耗时小于 0.5 秒。
- **CI 排错资料缺失**：新增失败时上传浏览器截图、错误上下文与 trace，保留 7 天；CI 同时安装 Chromium 和 WebKit。
- **小屏开场气泡遮挡 GO**：将倒计时数字、GO 与说明文字的实际边界加入气泡避让，三种浏览器项目的五种视口均检查五气泡与文字不重叠。
- **测试输出意外触发开发页面刷新**：Vite 文件监听排除 `test-results`、`playwright-report` 和 `.cache`，测试 trace 的 HTML 快照不会让正在运行的其他页面重载。
- **云端渲染资源争用**：CI 同时运行两个实时 WebGL 场景时出现计时明显变慢、布局读取超时。CI 改为单 worker，本机保留两个；布局检查合并为一次浏览器内快照，仍逐个验证所有控件与屏幕边界。

## 自动化结果

- `npm test`：**67 项通过 / 6 个文件**。在既有 57 项基础上新增 10 / 20 / 30 / 60fps 倒计时、低帧率停顿 / 暂停、同帧最早碰撞归因、免疫结束边界，以及 3 组约十分钟长局压力测试。
- 长局使用种子 7 / 43 / 2026，人工保持无敌以进入后期难度；检查位置有限且在场内、球不超过 24 个、三种球和两种动物出现、道具刷新、重复踢飞及积分。**这是稳定性压力测试，不是难度或真实存活成绩。**
- 浏览器套件共 **32 项：31 个有效用例通过，1 个桌面旋转用例按设计跳过**。首轮 30 通过、1 跳过、1 失败；失败为测试在 hit-stop 已结束后仍要求位置不变，修正后桌面 / 手机两项复测通过。云端完整回归状态见 [Check CatBall](https://github.com/qqqqqhanyu/CatBall/actions/workflows/ci.yml)。
- 云端慢环境另暴露 4 个 Kick 时序用例失败：错过半秒状态，以及量取控件期间动物已冲走。改为输入前逐帧观察并在暂停时准备后，桌面强制 SwiftShader 软件渲染的 4 个 M4 用例、手机 Chromium 的 2 个受影响用例均复测通过。
- TypeScript 检查、Vite 生产构建通过。构建目录 24 文件、6,610,044 字节，约 **6.61 MB**；本轮没有增加运行时素材。生产包没有开发场景或 `__catball` 接口。
- 本地生产预览的 Chromium / WebKit 冒烟通过：六角色、从 00:00 开始、Roll / Kick 冷却、暂停 / 继续；无 pageerror 或 HTTP 4xx/5xx。带开发场景参数也不会改变正式游戏初始状态。

## 真机待验

自动化没有连接实体手机，WebKit 也不等于实际 iOS Safari。以下需要用户在 [线上游戏](https://qqqqqhanyu.github.io/CatBall/) 试玩后确认：

1. iPhone Safari / Android Chrome 横屏，刘海、地址栏收缩与安全区。
2. 左手持续移动、右手 Kick / Roll 的舒适度，切应用后返回是否符合预期。
3. 连续 5–10 分钟的帧率、发热和电量；30 / 60 / 120 / 180 秒后的难度与技能手感。

尚未将这些真机项目标记为通过。没有为测试擅自调整难度，未增加音效。
